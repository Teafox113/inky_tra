# 發布流程

目前工作分支為 codex/zh-tw-workspace。GitHub 倉庫的 fork 關聯已確認，不需要重新建立。

1. 完成 docs/繁中測試計畫.md，核對制式資訊与第三方授權。版本來源為 app/version.json；套件、文件及發布檔名需同步。
2. 執行 npm test、npm run check:publish，確認差異只涉及編輯器與允許的原創示範／上游工具片段。
3. 使用 npm run build:win 建置，檢查 EXE 屬性、實際啟動、ZIP 名稱與封裝內檔案。
4. 將符合發布範圍的原始碼提交至本機 Git；確認 git status、git diff --cached，避免忽略規則之外的敏感檔案。
5. 使用者要求推送時，才推送開發分支至 origin，再依需求建立 PR 或合併預設分支。
6. 使用者要求發布時，才建立有版本標籤、Change Log 與 ZIP 的 GitHub Release。

原始碼倉庫不提交 node_modules、dist、.local、API 設定、聊天記憶或個人備份；ZIP 只從本工作區的 app 與授權／說明來源建立。舊翻譯工作區與商業遊戲資料不屬於發布來源。
